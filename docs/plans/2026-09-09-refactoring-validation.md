## 5. 阶段三：重构编辑器状态与动作

行为约定：分析、导入和重建期间暂停内容修改；保留查看、平移缩放及取消。结果提交前同时核验任务身份与文档版本。
UI 禁用与状态/命令层检查都须覆盖，不能只依赖某个按钮的 `disabled`。

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| P3-01 | 一次拖拽的多次移动事件；属性编辑；删除；批量锁定/解锁 | 用户的一次完整动作对应一次历史提交；撤销/重做恢复正确对象、位置和属性。 |
| P3-02 | 无变化提交、取消拖拽、连续撤销后再编辑 | 无变化/取消不创建历史；新编辑正确截断重做分支，选择不引用已删除对象。 |
| P3-03 | 任务运行中画布、属性面板、侧栏、快捷键、撤销/重做及导入入口 | 所有已支持的内容变更通道遵守互斥；查看和视口操作仍可用；不启动相互冲突的任务。 |
| P3-04 | 任务 A 取消后 B 启动，A 晚于 B 返回 | A 的成功或失败都不覆盖 B 的状态；B 按身份与文档版本校验后才可提交。 |
| P3-05 | 请求发出后文档版本变化；切换文档；组件卸载 | 旧结果不写回当前文档；相关监听与请求资源清理，不触发迟到状态更新。 |
| P3-06 | 当前任务成功、网络失败、响应非法、主动取消 | 仅成功且校验通过产生一次内容提交；失败/取消保留任务开始前文档和历史。 |
| P3-07 | 自动保存去抖、快速连续编辑、保存失败/仅内存回退、恢复 | 以最新文档保存；只有实际持久化成功才显示已保存；失败保留未保存提示与离页保护。 |
| P3-08 | 空文档清理持久化失败、首次恢复、重新编辑后重试 | 不把失败误报为已保存；恢复不意外覆盖存储；后续成功保存更新状态。 |

需要在 PowerShell 中复核现有 CI 断言入口时，可在记录并恢复环境变量的前提下执行：

```powershell
$refactorPreviousCi = $env:CI
$refactorPreviousEvaluateAi = $env:EVALUATE_AI
try {
    $env:CI = 'true'
    $env:EVALUATE_AI = '0'
    npm run evaluate
    if ($LASTEXITCODE -ne 0) { throw '评估进程失败，请检查样本报告。' }
} finally {
    $env:CI = $refactorPreviousCi
    $env:EVALUATE_AI = $refactorPreviousEvaluateAi
}
```

`EVALUATE_AI=0` 用于明确关闭现有可选真实 AI 分支。以上命令生成评估文件；完整性断言现已接通，报告包含预期文件、成功/失败与 validation。
新增的浏览器、Hooks 与测试类型检查脚本已接入 CI；本地通过不代表远端 CI 已运行。
现有 CI 的检查顺序可见 [ci.yml](../../.github/workflows/ci.yml)，不应把已经存在的评估接入重复算作本轮新增成果。
